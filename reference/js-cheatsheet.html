JavaScript patterns for the exam

Every snippet here is deliberately generic — swap sampleData or the API url for whatever the real brief gives you.

1Template literals + dot notation

Backticks let you drop variables straight into a string with ${}. Reading a property off an object uses a dot.

const sampleData = {
  title: "The Lantern Orchard",
  author: "Mere Kingsley",
  year: 2019,
};

const featured = document.getElementById("featured");

featured.innerHTML = `
  <h2>${sampleData.title}</h2>
  <p>${sampleData.author} · ${sampleData.year}</p>
`;
Why this matters Everything inside ${ } is real JavaScript, not just a variable name — so ${sampleData.year + 1} or ${sampleData.title.toUpperCase()} both work fine.

3Selecting elements & toggling a class

const button = document.getElementById("toggle-desc");
const description = document.querySelector("#featured .description");

button.addEventListener("click", () => {
  description.classList.toggle("show");

  if (description.classList.contains("show")) {
    button.textContent = "Show less";
  } else {
    button.textContent = "Show more";
  }
});
Watch the selector querySelector("#featured .description") means: inside the element with id featured, find something with class description. Mixing up which class you actually gave the element in your template literal is the single most common bug here — the class name in your HTML string and the class name in your selector must match exactly.

4async/await + fetch

async function loadItems() {
  const response = await fetch("API_URL_HERE");
  const data = await response.json();

  const grid = document.getElementById("card-grid");
  let cards = "";

  data.forEach((item) => {
    cards += `
      <article class="card">
        <img src="${item.cover_url}" alt="Cover for ${item.title}">
        <h2>${item.title}</h2>
        <p class="description">${item.description}</p>
      </article>
    `;
  });

  grid.innerHTML = cards; // set ONCE, after the loop
}

loadItems(); // don't forget to actually call it
The two words that make this "async" async on the function lets you use await inside it. await pauses that line until the promise (the fetch, or the .json() parse) finishes. Forget await and data will be a pending Promise object, not your array.
Build-then-assign, not assign-in-loop Notice cards starts as an empty string, gets += added to it on every pass, and is only assigned to innerHTML once, after the loop ends. If you set grid.innerHTML = cards inside the loop, every pass throws away everything built so far — you'll usually end up with only the last item rendered.

for...of — the alternative to forEach

for (const item of data) {
  cards += `<article class="card">${item.title}</article>`;
}

Functionally identical to .forEach() here — use whichever you find easier to read under pressure.

6Listening for a checkbox change

const checkbox = document.getElementById("show-descriptions");

checkbox.addEventListener("change", () => {
  // select these INSIDE the handler — the cards don't exist
  // until loadItems() has already run once
  const descriptions = document.querySelectorAll("#card-grid .description");

  descriptions.forEach((description) => {
    description.classList.toggle("show", checkbox.checked);
  });
});
querySelector vs. querySelectorAll querySelector returns a single element (the first match) — it has no .forEach. querySelectorAll returns a NodeList of every match, which does have .forEach. Looping over multiple cards' descriptions always needs the All version.
classList.toggle's second argument classList.toggle("show") flips the class on/off each call. classList.toggle("show", checkbox.checked) forces it to match a boolean instead — much safer for a checkbox, since clicking twice fast can't get it out of sync.
