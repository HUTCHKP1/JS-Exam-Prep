Bugs that actually show up in this task

These are the specific, repeatable mistakes worth checking for yourself before you submit each task — not a full debugging course, just the handful of things that cost the most marks for the least effort to catch.

CSS

Missing dot before a class name description.show { display: block; } targets an element whose tag name is <description> — which doesn't exist — combined with class show. It will never match anything and the rule silently does nothing. You want .description.show. If a toggle changes the button text but the content never actually appears, this is the first thing to check.
Rule order / specificity fighting itself If you write a general rule (.description { display: none; }) and a more specific one elsewhere (#featured .description { display: block; }), the more specific selector wins regardless of order in the file. Keep your hide/show rules as similar in specificity as possible (e.g. .description and .description.show) so toggling a class is guaranteed to work.

JavaScript

querySelector vs. querySelectorAll document.querySelector(...) always returns a single element (or null), never a list. Calling .forEach on it throws TypeError: ... .forEach is not a function. Anywhere you need to loop over more than one matching element — like every card's description in Task 6 — you need querySelectorAll.
Selector doesn't match the class you actually gave the element It's easy to build an element with class="description" in your template literal, then later write document.querySelector("#featured .featured") or similar by accident when copy-pasting between tasks. The class name inside your HTML string and the class name inside your selector are two separate pieces of text that have to match exactly — nothing checks this for you until it silently fails at runtime.
Selecting elements before they exist The cards from Task 4 don't exist in the DOM until the fetch has resolved and innerHTML has been set. If your Task 6 checkbox listener selects .card .description at the top of the file (outside any function), it will find nothing, because that code ran before loadItems() finished. Select inside the event handler instead, so the lookup happens at click/change time, not at page-load time.
Rebuilding innerHTML inside the loop grid.innerHTML = cards; placed inside a forEach/for...of loop overwrites the whole grid on every single pass. Because cards keeps growing correctly outside the DOM, the page will often visually show only the very last card once the loop finishes, even though your string-building logic was fine. Build the full string first, assign it once, after the loop.
Forgetting await Both fetch(url) and response.json() return Promises. Without await in front of each, you get a Promise object instead of the data itself, and trying to .forEach over it or read a property off it fails.
Function defined but never called Writing async function loadItems() { ... } does nothing on its own — the last line still needs to be loadItems(); to actually run it on page load.

HTML

Generic alt text alt="image" or alt="cover" technically satisfies "has an alt attribute" but not "describes the image" — markers usually check for an actual description of what's shown, not just presence of the attribute.
Event listener attached before the element exists If a button is created dynamically inside a template literal (like the Task 3 "show more" button), any addEventListener call for it must run after that template literal has been written into the page with innerHTML — not before. Order of operations in the file matters.

Git

One giant commit at the end A single end-of-exam commit typically earns no marks for the workflow task even if the code is perfect — the requirement is usually about the history (one commit per task, descriptive messages), not just the final state of the code. Commit as you finish each task, with a message describing what changed.
